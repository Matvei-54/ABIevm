# Локальный запуск ABIevm и проверка StakeDAO

Проверенная версия Go: **1.27.2**. Откройте терминал в корне проекта — папке с `go.mod`.
При первом запуске Go скачает зависимости. Реальный RPC URL храните в переменной
окружения, не в исходниках. `.env` автоматически не читается.

## Проверка одного или трёх реальных пулов с GetBlock

Команда запускается отдельно от сервера и Swagger. По умолчанию она берёт
до трёх gauge из вашего первоначального `gaugesMainFromController` (commit
`ec418eb`) и читает актуальную регистрацию через `Controller.gauge(address)`.
Адреса являются кандидатами, а не доказательством регистрации: источником vault,
asset, rewardReceiver и protocolId служит текущий контракт Controller.
История событий и исторический `eth_getCode` вообще не запрашиваются.
Все чтения состояния и расчёт наград выполняются на одном свежем блоке.

В PowerShell задайте URL своего **Ethereum Mainnet** endpoint:

```powershell
$env:STAKEDAO_ETHEREUM_RPC_URL = "ВАШ_GETBLOCK_MAINNET_RPC_URL"
```

Если в этой PowerShell уже есть правильный `$rpc`, вместо копирования URL:

```powershell
$env:STAKEDAO_ETHEREUM_RPC_URL = $rpc
```

Сначала проверьте один пул:

```powershell
go run -mod=readonly ./cmd/stakedao-check -limit 1 -output stakedao-sample.json
```

После успешного запуска появится `stakedao-sample.json` в текущей папке.
Команда напечатает полный путь. При ошибке новый файл не создаётся, предыдущий
успешный результат не перезаписывается. Это также относится к случаю, когда
команда завершилась с `exit status 1`: отсутствие JSON тогда ожидаемо.
Не используйте PowerShell pipe или перенаправление: за сохранение отвечает
`-output`, результат записывается в UTF-8 без BOM после успешного получения JSON.

Затем можно проверить до трёх и сохранить JSON для разбора:

```powershell
go run -mod=readonly ./cmd/stakedao-check -limit 3 -output stakedao-sample.json
```

В Linux/macOS:

```sh
export STAKEDAO_ETHEREUM_RPC_URL="ВАШ_GETBLOCK_MAINNET_RPC_URL"
go run -mod=readonly ./cmd/stakedao-check -limit 1 -output stakedao-sample.json
go run -mod=readonly ./cmd/stakedao-check -limit 3 -output stakedao-sample.json
```

Команда делает не больше **5 RPC-запросов/с** и **300 RPC-попыток** за запуск.
Это ограничение запросов, не вычислительных единиц GetBlock: цена CU зависит от
метода. Лимит времени — 5 минут; прервать можно Ctrl+C. Автоматического перебора
других окон или повторной полной загрузки нет. Цены читаются из контрактов
Chainlink/ERC4626/Curve NG и кэшируются в памяти. Чтения цен тоже входят в RPC-бюджет.
Свежие цены компонентов повторно используются при проверке следующих пулов.
Между отдельными запусками команды локальная map не сохраняется; в веб-приложении
она живёт до остановки процесса. Redis пока не подключён.

В JSON смотрите `network`, `blockNumber`, `pools`, `errors`. В каждом пуле:
`name`, `vaultAddress`, `assetAmount`, `tvl`, `aprStatus`, `apr`, `rewards`.
`tvl` — USD, `apr` — годовая оценка наград в процентах. `apy` пока `null`.
Отсутствующая цена LP/asset не заменяется ценой компонента: TVL/APR могут быть
`null`, причина будет в `errors`. Диагностические сообщения идут в stderr,
без `-output` JSON идёт в stdout. Наличие JSON не означает, что все значения доступны или уже
подтверждены независимым сравнением с UI StakeDAO.

В выборке может оказаться меньше пулов, чем запрошено: незарегистрированные
и shutdown gauge пропускаются. Если все кандидаты неактивны, команда завершится
ошибкой с пояснением. Другие конкретные gauge можно передать явно:

```sh
go run -mod=readonly ./cmd/stakedao-check -limit 1 -gauges 0x3285987Bbd0b695Ac48DC8571F519065B50aBA07 -output stakedao-sample.json
```

Через `-gauges` допускается максимум три уникальных ненулевых адреса через запятую.
Это адреса gauge, не LP-токены и не адреса vault. Curve V2 имеет поддержку основной
награды, Balancer primary — пока нет.

Предыдущая версия выбирала окно 23225415–23225514: пользователь подтвердил, что
в нём нет подходящих текущих регистраций. Успешный ответ `eth_getLogs` подтверждал
только доступность метода, а не наличие нужных vault. Это окно больше не используется
по умолчанию. Для ручной диагностики известного окна остаются совместные флаги
`-from`/`-to` (максимум 100 блоков включительно); с `-gauges` их совмещать нельзя.
Автоматического перебора окон нет.

Первый кандидат (`-limit 1`) — `evaUSDC/evaUSDT`, для которого в ручном
mainnet-запуске на блоке 26234474 получены TVL и APR. Пример результата трёх пулов
есть в `examples/stakedao-sample.json`. В нём avUSD/evaUSDC не имеет цены из-за
отсутствия USD feed для avUSD; для frxUSD/scrvUSD цена уже получена из контрактов; значения при новом запуске могут отличаться. Этот пример получен
через PublicNode, не через ваш GetBlock.

Если произошла ошибка, пришлите её текст без ключа и URL. Полный приватный endpoint
команда в диагностике скрывает. GetBlock Mainnet подтвердил `eth_getLogs` на
100 блоков, но отказал в историческом `eth_getCode`. Для новой проверки по gauge
оба метода не нужны. JSON может содержать `errors` и недоступные цены/компоненты
APR; наличие файла само по себе не подтверждает полноту или точность оценки.

## Запуск веб-сервера

```sh
go run -mod=readonly ./cmd
```

Echo слушает порт 8081. Проверить только запуск без RPC можно запросом
`GET /reservesStakedao/base`: ожидается HTTP 400, поддерживается только `ethereum`.

Для полной загрузки выберите в Swagger `GET /reservesStakedao/ethereum`.
Теперь он читает события по 1500 блоков, используя до 8 воркеров, и не требует
архивного `eth_getCode`. Для Ethereum сохранён блок начала 23225415 из прежнего
поиска через Alchemy; источник номера описан в README StakeDAO.

Параметры до запуска сервера (например, PowerShell):

```powershell
$env:STAKEDAO_ETHEREUM_RPC_URL = "ВАШ_GETBLOCK_MAINNET_RPC_URL"
$env:RPC_MAX_RPS = "18"
$env:STAKEDAO_DISCOVERY_WORKERS = "8"
go run -mod=readonly ./cmd
```

RPC_MAX_RPS ограничивает суммарные HTTP RPC-методы Aave/Curve/StakeDAO в этом
процессе, а не каждую платформу отдельно. При запуске из IDE задайте переменные
в её Run Configuration: переменные другой PowerShell сессии туда не передаются.
Работает только HTTP(S), не WebSocket. Для нескольких экземпляров сервера/CLI
лимит каждого процесса считается отдельно.

Полный запрос ограничен пятью минутами. ~2000 запросов событий при 18 RPS —
теоретически ~112 секунд, затем нужны чтения пулов и цен. Время и расход CU
полной mainnet-загрузки ещё не измерены; при нехватке CU или времени будет ошибка,
а не неполный список под видом полной загрузки. Регистрации пока не кэшируются.
Контрактные чтения Multicall в StakeDAO ещё не добавлены.

Ограниченная команда для 1–3 пулов остаётся удобной для дешёвой диагностики.

## Автоматические проверки

```sh
go test -mod=readonly -p 3 ./...
```

Тесты используют локальные HTTP/RPC-стенды, не бесплатные RPC.
Бизнес-модель и источники ABI: `internal/service/stakedao/README.md`.
Изменения публикуются в ветке `feat/stakedao-service`, без изменения `main`.
