# Сравнение CRV APR на одном блоке

Реализованы выбор блока и изолированные цены в диагностике. Выполнено сравнение
на блоке **26357109**, timestamp `1793983739`, hash
`0xf78c44fa843de3f97b27e97c509754e3d0584f3751e7bc1c81b8c471c6dd7741`.
Все контрактные данные и все цены относятся к этому блоку. Повторный запрос
двух пулов на том же блоке дал те же данные, что первые два пула в запросе пяти,
кроме времени формирования строки ответа.

Получено конкретное объяснение **различий формул**, но live UI на этом блоке
не получен. Публичный helper StakeDAO воспроизвёл опубликованные показатели;
тождество с текущим закрытым Hub не объявляется доказанным.

## Как повторить

В Swagger первый запрос выбирает текущий блок и читает свежие цены:

```text
GET /reservesStakedao/ethereum/diagnostics?limit=5&strictPrices=true
```

Из ответа скопируйте `blockNumber`, затем выполните:

```text
GET /reservesStakedao/ethereum/diagnostics?limit=2&block=26357109
GET /reservesStakedao/ethereum/diagnostics?limit=5&block=26357109
```

Номер выше — блок сохранённого примера; для нового сравнения подставьте свой.
`block` автоматически включает `strictPrices`, даже если отдельный флаг опущен.
Без `block/strictPrices` остаётся прежний режим с общей map и TTL 15 минут.
Нулевой/отрицательный/нечисловой блок и блок выше текущей вершины возвращают 400.

CLI, переменная `STAKEDAO_ETHEREUM_RPC_URL` задаётся как раньше:

```powershell
go run -mod=readonly ./cmd/stakedao-check -diagnostics -limit 5 -strict-prices -output strict-5.json
$block = (Get-Content -Raw -Encoding UTF8 strict-5.json | ConvertFrom-Json).blockNumber
go run -mod=readonly ./cmd/stakedao-check -diagnostics -limit 2 -block $block -output strict-2.json
```

Для давних блоков RPC должен хранить историческое состояние. Если провайдер
отвечает `historical state ... is not available`, используйте свежий блок
и повторите запрос сразу либо RPC с нужной историей. Код не заменяет выбранный
блок на latest. Обычная работа всего реестра не меняется.

Строгий режим создаёт отдельную map цен на запрос, включая все зависимости LP.
Он не читает и не перезаписывает общий кэш текущих цен. TTL и свежесть раундов
проверяются относительно времени выбранного блока, поэтому старый блок не
требует сегодняшней цены. `latestRoundData` вызывается на выбранном блоке;
это последний допустимый раунд оракула на тот момент, а не требование наличия
нового раунда ровно в этом блоке. Hash блока проверяется повторно в конце.

## Какие источники удалось подтвердить

1. В [API V2](https://github.com/stake-dao/api/blob/10a160136ee649d79c04341812f39d2b013a179a/src/lib/strategies/v2.ts)
   `getStratsFromHub()` получает готовые vault-данные из
   `data-hub.contact-69d.workers.dev/v1/vaults`. Публичный API в этом пути
   не вызывает reader и не передаёт выбранный нами блок. Расчёт Hub в этом
   репозитории отсутствует; Hub из среды проверки возвращает сетевой HTTP 403.
2. В опубликованном пакете
   [@stake-dao/reader@0.5.52](https://registry.npmjs.org/@stake-dao/reader/0.5.52)
   изучен и локально выполнен оригинальный
   [getOnlyboostData.js](https://unpkg.com/@stake-dao/reader@0.5.52/dist/esm/strategies/curve/fetch/getOnlyboostData.js).
   Для mainnet он вычисляет Convex APR из переданной ставки и TVL Sidecar,
   ограничивает её `maxApr`, затем переводит в boost и взвешивает по размещению.
3. На сохранённом [срезе API](https://github.com/stake-dao/api/blob/cc776d695be8c2d79e05c340866f6e1d6247c97d/api/strategies/v2/curve/1.json)
   у четырёх ненулевых CRV-показателей точно выполняется
   `CRV APR = minApr × boost × 0.835`; у FXS/ETH оба результата нулевые.
   Коэффициент соответствует наблюдавшемуся protocol fee 16.5%.
4. Оригинальный публичный helper воспроизвёл все пять опубликованных boosts,
   а вместе с указанным равенством — все пять CRV APR с точностью JS Number.
   Передача **общей** ставки BaseRewardPool воспроизводит этот boost; передача
   собственной доли Sidecar даёт другие значения. Это подтверждение модели
   по наблюдаемым данным, не доказательство содержимого приватного Hub.

Для исполнения проверялся только current weighted boost; расчёты optimal
allocation и другие продукты reader не проверялись. Адрес репозитория monorepo
из npm-метаданных недоступен публично. SHA-256 исходника helper, версия пакета,
исходные показатели и результаты сохранены в
[reader-evidence.json](../../../examples/stakedao-same-block/reader-evidence.json).

## Согласованный состав доходности

Сравнивается **только основной CRV APR** при одинаковых TVL, ценах и блоке.
Ставки extra-наград vault читаются отдельно: во всех пяти сохранённых пулах
CVX имеет `not_started` и нулевую текущую ставку. Накопленный баланс и новая
эмиссия CVX не добавляются к текущему APR как уже запущенное распределение.

Trading APY и доходность underlying не включены. Торговой APY нужен одинаковый
исторический период с окончанием в B, а не только один снимок балансов.
В опубликованном срезе итог складывает CRV APR и Trading Fees APY; это другой
состав показателя. В нашем ответе `aprScope=rewards`, `apy` остаётся null.

## Найденные различия

Наш путь соответствует проверенным связям контрактов:

```text
L = текущая эмиссия Locker из inflation, weight и working balance / supply
C = BaseRewardPool.rewardRate × Sidecar.balance / BaseRewardPool.totalSupply
net CRV = L + C − L × protocolFee − (L + C) × harvestFee
```

Ставки переводятся в CRV/second. Комиссии Convex уже удержаны до BaseRewardPool;
повторно они не вычитаются. Protocol fee Accountant относится к Locker,
harvest fee — согласно политике vault к соответствующим primary-потокам.

Проверенная публичная модель отличается:

- Использует всю переданную ставку BaseRewardPool при делении на TVL Sidecar,
  а не предварительное выделение доли `Sidecar.balance / totalSupply`.
- Ограничивает результат максимальной доходностью gauge и получает weighted boost.
- В опубликованном срезе применяется общий множитель `(1 − protocolFee)`;
  отдельный harvest fee этим равенством не выражен.

Для наших одинаковых данных эту модель можно записать так:

```text
minRate = базовая CRV-ставка на LP при 40% working balance
Cref = min(общая сохранённая ставка BaseRewardPool, minRate × 2.5 × Sidecar LP)
reference net CRV = (L + Cref) × (1 − protocolFee)
```

В helper нет проверки `periodFinish` в этом вычислении; это также не основание
принимать сохранённую ставку за текущую выплату. В сохранённом сравнении все
четыре реально используемых Sidecar имеют активные периоды. У FXS/ETH Sidecar
нет, его Convex pid=69 остаётся только внешним ориентиром.

Это объясняет, почему одинаковые цены сами по себе не давали совпадения APR.
Подтверждённый контрактный расчёт не заменён формулой отображения.

## Числа на одном блоке

Прогоны выполнены через PublicNode, без GetBlock CU: пять пулов — 178 попыток,
около 36 секунд; два пула на том же блоке — 69 попыток. Обоим ответам присвоен
одинаковый проверенный hash. Все цены имеют `blockNumber=26357109`, во всех
пулах `aprStatus=available`, контроль PoolUtilities — `matched`, ошибок полей нет.

| Пул | Наш CRV APR | Публичная модель на том же блоке | Разница модели, п.п. |
| --- | ---: | ---: | ---: |
| crvUSD/USDC | 3.669361% | 3.730225% | +0.060864 |
| FXS/ETH | 0% | 0% | 0 |
| evaUSDC/evaUSDT | 9.207868% | 8.838116% | −0.369752 |
| frxUSD/sUSDS | 1.457415% | 1.577210% | +0.119795 |
| crvUSD/USDT | 4.305299% | 4.333588% | +0.028289 |

Например, для eva-пула разница раскладывается без изменения цены:
удаление harvest fee `+0.002487` п.п., protocol fee также на Sidecar
`−0.905159` п.п., общая ставка BaseRewardPool и ограничение `+0.532921` п.п.
Итого `−0.369752` п.п. Это эффекты конкретной модели, не измерение ошибки live UI.

В подробном ответе появился `diagnostics.readerModel`, только в строгом режиме:
`actualCrvApr`, `withoutHarvestFeeApr`, `globalProtocolFeeApr`, `referenceApr`
и `differencePercentagePoints`. Это последовательные сценарии изменения формулы,
не дополнительные награды. Поля `source/scope/message` фиксируют ограничения.
При неполных данных/другом блоке цены модель остаётся `unavailable`.
Текущий эталон рассчитан на 18-decimal LP, CRV и не более одного Sidecar;
для неподтверждённых размещений он не подставляет оценку.

Сохранённые результаты:
[пять пулов](../../../examples/stakedao-same-block/5pools.json),
[два пула](../../../examples/stakedao-same-block/2pools.json),
[разложение расхождений](../../../examples/stakedao-same-block/comparison.json).
Из чисел независимо пересчитаны net rate и APR; оригинальный JS helper на тех
же входных данных совпал с эталонной Go-моделью. Дополнительных RPC для самой
модели не требуется.

Прямой UI-срез с подтверждённым B и полная актуальная формула Hub остаются
недоступны. Для утверждения «совпало с UI на блоке B» потребуется именно такой
срез либо открытый/предоставленный код Hub. Выполненное сравнение позволяет
уже сейчас отделить изменение цен от изменения методики расчёта.
